# MOEX Scalper Dashboard

Real-time interface for tracking open positions of physical and legal entities on MOEX futures contracts via the FUTOI API.

## Features

- 📊 **Real-time data** — auto-refresh every 30 seconds
- 🌙 **Dark theme** — comfortable at any time of day
- 👤 **Physical entities** — long/short position volumes
- 🏢 **Legal entities** — long/short position volumes
- 📈 **OI chart** — historical data with divergence detection
- ⚖️ **Comparison** — delta between categories
- 🔐 **Password-protected** — token-based access control

## Quick Start (Local)

### 1. API Key

Create `api_key.txt` in the project root with your MOEX Algopack JWT token:

```
your_api_key_here
```

### 2. Start the server

```bash
python server.py
```

Or run `start.bat` on Windows.

### 3. Open in browser

- **Dashboard**: http://localhost:8081/scalper-dashboard.html
- **Health check**: http://localhost:8081/health
- **API test**: http://localhost:8081/test-api.html

```bash
# Production
curl https://moex-scalper-dashboard.onrender.com/health

# Staging
curl https://moex-staging.onrender.com/health
```

Response:
```json
{
  "status": "ok",
  "uptime": "2h 15m 30s",
  "api_key": "configured",
  "auth": "enabled",
  "port": 10000,
  "python": "3.14.10"

```

> ⚠️ If `"api_key": "missing"` → `MOEX_API_KEY` env var is not set on Render.

### Environment Variables (Render)

| Key | Description |
|-----|-------------|
| `MOEX_API_KEY` | MOEX Algopack JWT token |
| `ACCESS_TOKEN` | Password for dashboard access |
| `SESSION_SECRET` | Auto-generated by Render |

## 🔀 Branch Strategy

```
main        ← Production (stable, deploys to Render Production)
  └── dev   ← Staging (new features tested here first)
```

| Branch | When to use | Deploys to |
|--------|-------------|------------|
| `main` | Only stable, tested changes | Render Production |
| `dev` | New features, bug fixes — for testing | Render Staging |

### Normal workflow

```bash
# 1. Develop on dev
git checkout dev
# ... code ...
python server.py   # test locally

# 2. Push → Staging deploys automatically
git push origin dev
# → Test at https://moex-staging.onrender.com

# 3. If OK → merge to main
git checkout main
git merge dev
git push origin main
# → Production deploys automatically
```

## 🔴 Rollback (when Production breaks)

### Quick rollback

```bash
# 1. Find last stable commit
git log --oneline -10

# 2. Revert the bad commit
git checkout main
git revert <bad-commit-hash>

# 3. Push → Render deploys automatically
git push origin main
```

### Hard rollback (to a specific commit)

```bash
git checkout main
git reset --hard <stable-commit-hash>
git push origin main --force
```

## Troubleshooting

### Data not showing

1. Make sure server is running (`python server.py`)
2. Check that `api_key.txt` exists with a valid key
3. Open browser console (F12) for errors
4. Check health: `http://localhost:8081/health`

### "Failed to fetch" error

You're opening the HTML file directly. Run `python server.py` and open via `http://localhost:8081/`.

### Render Free Tier limitations

- Server **sleeps after 15 min** of inactivity
- First request after sleep: **~30 seconds** (cold start)
- For always-on: upgrade to a paid plan

## Technical Details

- **API**: MOEX Algopack FUTOI (Futures Open Interest) + ISS
- **MOEX data refresh**: every 5 minutes
- **UI refresh**: every 30 seconds
- **Proxy server**: solves CORS, keeps API key secure
- **Auth**: SHA-256 signed token, 30-day cookie
